# XERT Roster — acceptance map

Levels: **DB** = PGlite running the real migration (`npm test`);
**Engine** = browser engine unit tests (`npm test`); **Browser** = Chromium
workflow over the real migration (`test/staff-roster.browser.mjs`);
**Native** = iOS build/tests (not available in this environment).

| # | Scenario | Covered by | Level | Status |
| --- | --- | --- | --- | --- |
| 1 | Five presets work; a sixth needs no code change or duplicate sessions | engine "class-slot shortcuts span the real duty, and a sixth preset needs no code change"; db "a sixth class-time preset is configuration, and series generation is idempotent" | Engine, DB | Passed |
| 2 | Days/durations come from the schedule; generation retries idempotent | All demand comes from `class_sessions`; db "a sixth class-time preset … series generation is idempotent", "“this and future” previews, keeps history…" | DB | Passed |
| 3 | Usual week, exceptions, explicit no-availability, save failure, resubmission keep correct versions | engine "usual week plus a date exception…", "explicit “unavailable all month” is distinct from silence"; db "drafts autosave without changing effective availability; a failed resubmission keeps the previous version", "changing the usual week never alters a submitted snapshot"; Browser step "coach gives availability on a phone" | Engine, DB, Browser | Passed |
| 4 | UNKNOWN, partial duty, approved absence, expired capability cannot be assigned | engine + db "UNKNOWN, partial coverage, approved absence and expired capabilities cannot be assigned"; snapshot "browser preview agrees with the database on every coach × class × position" | Engine, DB | Passed |
| 5 | Adding/moving/extending a class after submission follows explicit-window / reconfirmation rules | db "moving a class invalidates its old session confirmation…"; snapshot "extending a class past the submitted window is never covered by the earlier review" (database check, browser check, coverage, Needs Attention, suggestions and publish all flag it); snapshot `addedSinceSubmission` drives the coach's "added since you answered" review | DB, Engine | Passed.
